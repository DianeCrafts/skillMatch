# 🔔 SkillMatch – Notification Service

## 📌 Overview

The **Notification Service** is a microservice within the SkillMatch platform responsible for managing user notifications.

In the current version (v1), it provides **database-backed, in-app notifications** and exposes REST APIs for retrieving and managing them.

This service is designed to be **simple, independent, and extensible**, with future support planned for:

* Email notifications
* Event-driven architecture (Kafka/RabbitMQ)
* Real-time push notifications (WebSocket/SSE)

---

## 🏗️ Architecture

This service follows the same architecture patterns used across the SkillMatch platform:

* Microservice-based design
* Dedicated PostgreSQL database
* REST API communication
* JWT-based stateless authentication
* API Gateway integration

### 🔐 Authentication Flow

* JWT is generated by the Auth Service
* API Gateway validates the token
* Notification Service:

    * validates JWT
    * extracts:

        * `userId`
        * `role`
* Authorization is enforced at the service level

---

## 🎯 Responsibilities

The Notification Service is responsible for:

* Storing notifications for users
* Allowing users to:

    * view their notifications
    * mark a notification as read
    * mark all notifications as read
* Receiving notification creation requests from other services

---

## 📦 Features (v1)

* ✅ Create notifications (internal API)
* ✅ Retrieve user notifications
* ✅ Mark single notification as read
* ✅ Mark all notifications as read
* ✅ Ownership validation (users can only access their own data)
* ✅ JWT-based security
* ✅ Swagger/OpenAPI documentation

---

## ❌ Not Included (v1)

* Email sending
* Real-time push notifications
* Event-driven messaging (Kafka/RabbitMQ)
* Redis caching
* Notification preferences

## 🧩 Core Entity

### Notification

Represents a notification stored for a user.

Fields:

* `id`
* `recipientUserId`
* `type`
* `title`
* `message`
* `read`
* `createdAt`

---

## 🏷️ Notification Types

```text
NEW_APPLICATION
APPLICATION_STATUS_UPDATED
```

---

## 🌐 API Endpoints

### 🔐 Authenticated Endpoints

#### Get current user's notifications

```
GET /api/notifications/me
```

#### Mark a notification as read

```
PATCH /api/notifications/{notificationId}/read
```

#### Mark all notifications as read

```
PATCH /api/notifications/read-all
```

---

### 🔧 Internal Endpoint (Service-to-Service)

#### Create a notification

```
POST /api/notifications/internal
```

Request body:

```json
{
  "recipientUserId": 1,
  "type": "NEW_APPLICATION",
  "title": "New application received",
  "message": "A new application was submitted for your job."
}
```

---

## 🔐 Security

* JWT-based authentication
* Stateless session management
* Each request must include:

```
Authorization: Bearer <token>
```

* Ownership validation ensures users can only access their own notifications

## ⚙️ Configuration

### application.yml

```yaml
server:
  port: 8086

spring:
  application:
    name: notification-service

  datasource:
    url: jdbc:postgresql://localhost:5432/skillmatch_notification_db
    username: postgres
    password: password

  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true

app:
  jwt:
    secret: YOUR_BASE64_SECRET

springdoc:
  swagger-ui:
    path: /swagger-ui.html
```
