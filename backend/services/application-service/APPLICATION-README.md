# 📌 SkillMatch – Application Service

## 📖 Overview

The **Application Service** is a core microservice in the **SkillMatch** platform responsible for managing job applications between **job seekers** and **recruiters**.

It enables:

* Job seekers to apply to jobs and track their applications
* Recruiters to review and manage applicants
* The system to maintain a history of application status changes

This service is part of a **microservices-based architecture** built with Spring Boot.

---

## 🏗️ Architecture

### 🔹 System Architecture

SkillMatch follows a **microservices architecture**:

* Each service is **independent**
* Each service has its own **PostgreSQL database**
* Communication is done via **REST APIs**
* Authentication is **JWT-based (stateless)**

### 🔹 Service Communication

* External requests go through the **API Gateway**
* The Application Service communicates with:

    * **Job Service** → to validate job existence, ownership, and status

### 🔹 Security Model

* JWT is generated by the **Auth Service**
* API Gateway forwards the token
* Application Service:

    * Validates JWT
    * Extracts:

        * `userId`
        * `role` (`JOB_SEEKER` / `RECRUITER`)

## 🚀 Features

### 👤 Job Seeker Features

* Apply to a job
* Prevent duplicate applications
* Withdraw an application
* View personal application history

### 🧑‍💼 Recruiter Features

* View applicants for their jobs
* Update application status
* Manage application workflow

### 🔄 Application Status Flow

* `APPLIED`
* `UNDER_REVIEW`
* `SHORTLISTED`
* `INTERVIEW`
* `REJECTED`
* `HIRED`
* `WITHDRAWN`

### 📜 Status History

* Every status change is recorded
* Includes:

    * status
    * timestamp
    * user who made the change

## 🧱 Core Domain Models

### Application

Represents a job application submitted by a job seeker.

Fields:

* `id`
* `jobId`
* `applicantId`
* `status`
* `appliedAt`
* `withdrawnAt`
* `updatedAt`

---

### ApplicationStatusHistory

Tracks changes in application status.

Fields:

* `id`
* `applicationId`
* `status`
* `changedAt`
* `changedBy`

---

## 🔐 Authorization Rules

### JOB_SEEKER

* Can apply to jobs
* Can withdraw their own applications
* Can view their own applications

### RECRUITER

* Can view applications for their jobs
* Can update application status
* Cannot modify applications they do not own

### SYSTEM RULES

* Cannot apply twice to the same job
* Can only apply to **PUBLISHED** jobs
* Withdrawn applications cannot be updated
* Recruiters cannot set status to `WITHDRAWN`

---

## 🔗 Inter-Service Communication

### Job Service Integration

The Application Service validates jobs using:

```
GET /api/jobs/internal/{jobId}
```

Used to verify:

* Job exists
* Job is published
* Recruiter ownership

## 🌐 API Endpoints

### 📌 Job Seeker

| Method | Endpoint                          | Description          |
| ------ | --------------------------------- | -------------------- |
| POST   | `/api/applications`               | Apply to a job       |
| PATCH  | `/api/applications/{id}/withdraw` | Withdraw application |
| GET    | `/api/applications/me`            | Get own applications |

---

### 📌 Recruiter

| Method | Endpoint                        | Description               |
| ------ | ------------------------------- | ------------------------- |
| GET    | `/api/applications/job/{jobId}` | View applicants for a job |
| PATCH  | `/api/applications/{id}/status` | Update application status |
